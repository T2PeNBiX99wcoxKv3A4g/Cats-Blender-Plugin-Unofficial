# 최적화

**최적화** 패널은 모델의 복잡도를 줄이고 성능을 향상하는 도구를 제공합니다. 대상에 따라 하위 패널로 묶인 컨테이너입니다:

- **머티리얼** - 머티리얼 결합, 텍스처를 PNG로 변환
- **메시 정리** - 결합, 분리, 중복 버텍스 제거, 노멀, 변형
- **셰이프 키** - 미사용 제거, 복구, 정적 최적화
- **본 및 웨이트** - 본과 웨이트 병합, 미사용 본/그룹 삭제
- **아틀라스 생성기** - 내장 텍스처 아틀라스 도구 (여전히 **알파**로 표시됨)

> 📝 **이 패널들은 최근에 재구성되었습니다.** *머티리얼 작업*은 이제 **머티리얼**이며(메시 작업은 분리됨), *메시 및 본 정리*는 이제 **본 및 웨이트**이고, 이전의 중첩된 *메시 도구* 패널은 **메시 정리**와 **셰이프 키**로 분리되었습니다. *아틀라스 생성*은 목록 맨 아래로 이동했습니다.

> 📝 **`5.3.1.0` 이후 Material Combiner 통합은 제거되었습니다.** *아틀라스 생성기 (레거시)* 하위 패널이 제거되었고, 이전의 *아틀라스 생성기 (신규)*였던 내장 도구는 이제 단순히 **아틀라스 생성기**입니다.

## 머티리얼

모델의 머티리얼과 텍스처를 최적화하는 도구입니다.

### 머티리얼 결합
여러 머티리얼을 더 적은 수의 머티리얼로 병합합니다:
- 드로우 콜 감소
- 성능 향상
- 텍스처 할당 유지
- UV 맵 보존
- 비슷한 머티리얼을 공유하는 오브젝트에 이상적

**사용 방법:**
1. 모델을 선택합니다
2. **머티리얼 결합**을 클릭합니다
3. 같은 속성을 가진 머티리얼이 병합됩니다

### 모두 PNG로 변환
모델의 모든 텍스처를 PNG 형식으로 변환합니다:
- 여러 플랫폼에서 최대 호환성 보장
- 알파 채널 유지
- 게임 내 텍스처 문제 예방에 도움
- VRChat의 표준 형식

**사용 방법:**
1. 모델을 선택합니다
2. **모두 PNG로 변환**을 클릭합니다
3. 모든 텍스처가 변환되고 저장됩니다

## 메시 정리

메시 오브젝트를 재구성하거나 정리하는 모든 작업입니다.

### 메시 결합

**전체:**
- 모든 메시를 하나의 오브젝트로 결합합니다
- 머티리얼 할당을 유지합니다
- 버텍스 그룹과 웨이트를 보존합니다
- 최종 최적화에 이상적입니다

**선택:**
- 선택한 메시만 병합합니다
- 부분 최적화에 적합합니다
- 다른 메시는 분리된 상태로 유지합니다
- 선택적 최적화에 유용합니다

**사용 방법:**
1. 메시를 선택합니다 (**선택**의 경우)
2. 적절한 결합 버튼을 클릭합니다
3. 메시가 결합됩니다

### 분리 기준

메시를 여러 오브젝트로 분할합니다.

- **머티리얼** - 머티리얼당 하나의 오브젝트. 복잡한 모델을 정리하거나 특정 부분을 최적화하는 데 적합합니다.
- **분리된 파츠** - 분리된 조각당 하나의 오브젝트. 떠 있는/숨겨진 지오메트리를 찾는 데 유용합니다.
- **셰이프** - 셰이프 키에서 별도의 메시를 생성합니다 (고급, 편집이나 분석에 유용).

> ⚠ 분리는 항상 쉽게 실행 취소할 수 있는 것은 아니므로 먼저 저장하세요.

### 중복 버텍스 제거
메시의 중복 버텍스를 제거합니다:
- 정밀한 제어를 위한 조정 가능한 임계값
- 버텍스 수 감소
- 일반적인 메시 문제 수정
- 성능 향상

**사용 방법:**
1. 메시를 선택합니다
2. 병합 거리 임계값을 설정합니다
3. **중복 버텍스 제거**를 클릭합니다
4. 임계값 내의 중복 버텍스가 병합됩니다

### 노멀

- **재계산** - 면 방향을 일관되게 만들어 뒤집힌 면과 셰이딩 문제를 수정합니다. 보통 원하는 작업입니다 (메시 편집, 불리언 작업 또는 가져오기 셰이딩 문제 후).
- **뒤집기** - *모든* 노멀을 반전합니다. 메시 전체가 뒤집혀 있는 경우에만 사용하세요.

### 변형

**변형 적용**은 오브젝트의 위치, 회전, 스케일을 메시에 베이크하고 변형을 기본값으로 초기화합니다. **모델을 병합하기 전**과 **셰이프 키를 만들기 전**, 그리고 스케일링 후에 중요합니다.

옆의 작은 버튼은 **모든** 오브젝트에 한 번에 변형을 적용합니다.

> ⚠ 변형 적용은 쉽게 실행 취소할 수 없으므로 먼저 저장하세요.

### 각 기능의 사용 시점

- **메시 결합:** 내보내기 전 최종 최적화
- **분리 기준:** 모델의 일부를 분리해야 할 때
- **중복 버텍스 제거:** 메시에 겹치거나 중복된 버텍스가 있을 때
- **노멀 재계산:** 셰이딩이 잘못되어 보일 때
- **변형 적용:** 모델을 병합하거나 셰이프 키를 만들기 전

> ⚠ **중요:** 이러한 작업은 영구적입니다. 이 도구를 사용하기 전에 항상 작업을 저장하세요. 원본 파일의 백업을 보관하는 것을 고려하세요.

## 셰이프 키

- **미사용 셰이프 키 제거** - 실제로 메시를 변형하지 않는 셰이프 키를 제거하여 파일 크기를 줄입니다.
- **손상된 셰이프 키 복구** - 일부 Blender 작업이 *모든* 셰이프 키에 한 번에 베이크하는 잘못된 오프셋을 되돌립니다. 아래를 참조하세요.
- **정적 셰이프 키 최적화** - 셰이프 키가 실제로 움직이는 버텍스만 유지하여 파일 크기를 크게 줄입니다. 안전하며 내보내기 전에 권장됩니다.

### 손상된 셰이프 키 복구 자세히

특정 Blender 작업은 모든 비 베이시스 셰이프 키를 동일한 잘못된 양만큼 이동시켜, *어떤* 키든 0보다 크게 설정하는 순간 메시가 이상한 포즈로 튀게 됩니다.

이 도구는 모든 비 베이시스 키를 버텍스별로 비교하여 **대부분이 동의하는** 위치를 찾아 그 공통 오프셋을 계산한 다음, 각 키에서 이를 뺍니다. 손상 위에 실제 표정을 담고 있는 키는 그 표정을 유지하며, 공유된 오류만 제거됩니다.

**사용 시점:** 모든 셰이프 키가 같은 방식으로 잘못된 경우. 이것이 이 도구가 다루도록 만들어진 손상 형태입니다.

> ⚠ **일반적인 복구 버튼이 아닙니다.** 키가 하나 또는 둘만 손상되었거나 각각 다르게 손상되었다면 다수결로 찾을 대상이 없으므로 결과가 잘못됩니다. 그런 경우에는 직접 수정하세요.

> 💡 비교할 비 베이시스 셰이프 키가 최소 하나 필요합니다. Basis만 있는 메시에서는 아무것도 하지 않으며 그렇게 알려 줍니다.

### VRChat 업로드 준비

1. 미사용 셰이프 키 제거
2. 정적 셰이프 키 최적화
3. 노멀 재계산 ([메시 정리](#mesh-cleanup) 참조)
4. 내보내기 진행

## 본 및 웨이트

본 및 웨이트 하위 패널(이전 이름 "메시 및 본 정리", 그 전에는 "본 병합")은 아바타의 아마추어를 최적화하고 본 개수를 줄이는 고급 도구를 제공합니다.

### 본 병합

#### 병합 옵션

**메시 병합:**
- 여러 메시가 있을 때 사용 가능
- 본 작업 전에 메시를 결합
- 웨이트 할당 유지

**본 병합:**
- 병합할 본을 제어
- 본 영향력을 기반으로 한 스마트 선택
- 중요한 본을 자동으로 보존

**병합 비율:**
- 병합 임계값 설정 (0.0 ~ 1.0)
- 값이 높을수록 더 적극적으로 병합
- 값이 낮을수록 더 보수적
- 권장: 0.5로 시작하여 조정

#### 주요 기능

**루트 새로 고침:**
- 루트 본 참조 업데이트
- 계층 구조 문제 수정
- 올바른 본 관계 보장
- 아마추어를 변경한 후 사용

**본 병합:**
- 병합 과정 실행
- 설정에 따라 선택한 본을 결합
- 웨이트를 지능적으로 재분배
- 전체 본 개수 감소

### 웨이트 병합

**부모로:**
- 모든 웨이트 그룹 결합
- 웨이트 분배 최적화
- 전체 웨이트 수 감소
- 최종 최적화에 적합

**활성 오브젝트로:**
- 활성 오브젝트로 웨이트 전송
- 특정 메시 최적화에 이상적
- 웨이트 영향력 유지
- 선택적 최적화에 사용

#### 추가 옵션

**병합된 본 유지:**
- 병합된 본을 백업으로 보관
- 변경 사항을 되돌릴 수 있음
- 결과 테스트에 유용
- 최대 최적화를 원하면 비활성화

**표시된 메시만 병합:**
- 표시된 오브젝트만 처리
- 선택적 최적화에 도움
- 숨겨진 백업 유지
- 반복 작업 워크플로에 적합

### 삭제

**제로 웨이트 본:**
- 웨이트 영향력이 없는 본 삭제
- 아마추어 복잡도 감소
- 성능 향상
- 대부분의 경우 안전하게 사용 가능

**제약 조건:**
- 본 제약 조건 제거
- 아마추어 동작 단순화
- 연산 요구 감소
- 제약 조건이 필요하지 않을 때 사용

**제로 웨이트 버텍스 그룹:**
- 비어 있는 버텍스 그룹 정리
- 파일 크기 감소
- 뷰포트 성능 향상
- 안전한 정리 작업

**트위스트 본 유지 옵션:**
- 중요한 애니메이션 본 보존
- 부드러운 변형 유지
- 애니메이션 문제 방지
- 더 나은 애니메이션 품질을 위해 활성화

**빈 부모 본 유지:**
- 웨이트가 없어도 부모 본 유지
- 계층 구조 무결성 유지
- 구조적 문제 방지
- 복잡한 리그에 활성화

**숨겨진 본 건너뛰기:**
- 정리 중 숨겨진 본 무시
- 특정 리그 설정 보존
- 숨겨진 본이 영향을 받지 않도록 보장
- 헬퍼 본이 있을 때 사용

### 본 도구

**본 복제:**
- 선택한 본의 복사본 생성
- 사용자 지정 리깅에 유용
- 원래 구조 유지
- 사용자 지정 리그를 위한 고급 기능

**본 연결:**
- 각 본의 꼬리를 자식 쪽으로 향하게 하여, 팔/다리가 떠 있는 본의 나열이 아닌 하나의 연속된 체인으로 보이게 합니다
- **부모에게 자식이 하나뿐인** 경우에만 본을 부모에 연결하며, 이때 본의 머리는 이미 부모의 꼬리에 위치합니다
- 분기되는 관절(척추에서 뻗는 어깨와 엉덩이, 손목에서 뻗는 손가락 시작점)은 의도적으로 그대로 둡니다
- MMD 모델 수정의 ⚙ 모델 설정에 있는 **본 연결** 체크박스와 동일한 작업을 실행하므로 둘 다 필요하지 않습니다

> ⚠ 본을 연결하는 것은 **겉모습만의 문제가 아닙니다.** Blender는 본의 머리를 부모의 꼬리에 맞추므로 본이 이동합니다. 그래서 Cats는 아무것도 움직일 필요가 없는 경우에만 연결합니다. 모두 연결하면 양팔과 양다리가 척추 중앙으로 끌려 들어가게 됩니다.

> 발가락 보행 다리와 트위스트 본 *생성* 도구는 여기에 없으며, 자체 [본 도구](Bone-Tools) 패널을 갖습니다.

### 모범 사례

1. **항상 백업으로 시작** - 본 병합은 아마추어를 크게 수정합니다
2. **병합 비율 테스트** - 복사본에서 먼저 다양한 값을 시도하세요
3. **병합 후 애니메이션 확인** - 움직임이 여전히 올바르게 작동하는지 확인하세요
4. **정리 도구는 마지막에** - 모든 수정을 정리 전에 완료하세요
5. **트위스트 본 유지** - 필요 없다고 확신하지 않는 한
6. **변경 후 루트 새로 고침** - 본 계층 구조를 최신 상태로 유지하세요

### 워크플로 예시

1. **병합 비율**을 0.5로 시작합니다
2. 안전을 위해 **병합된 본 유지**를 활성화합니다
3. **본 병합**을 클릭합니다
4. 결과를 확인합니다
5. 만족스러우면 **제로 웨이트 본**을 실행합니다
6. 그다음 **제로 웨이트 버텍스 그룹**
7. 마지막으로 필요하지 않으면 **제약 조건**

> ⚠ **경고:** 이 작업들은 아마추어 구조를 크게 수정합니다. 진행하기 전에 항상 원본 파일의 백업을 보관하세요. 확신이 없다면 복사본에서 먼저 테스트하세요.

## 아틀라스 생성

텍스처 아틀라스는 여러 텍스처를 하나의 더 큰 텍스처로 결합하여 여러 머티리얼이 하나가 될 수 있게 합니다. 그 결과:
- 드로우 콜이 크게 감소합니다
- 아바타 성능이 향상됩니다
- 플랫폼의 텍스처 및 머티리얼 제한을 충족하는 데 도움이 됩니다
- 머티리얼 관리가 단순해집니다

Cats에는 최적화 아래에 하나의 아틀라스 하위 패널, 즉 내장 **아틀라스 생성기**가 있습니다:

| | 아틀라스 생성기 |
|---|---|
| **상태** | **알파** |
| **설치 필요 여부** | 없음, Cats에 내장됨 |
| **맵** | 알베도, 노멀, 이미션, 러프니스, 메탈릭, AO, 높이 |
| **패딩** | 가장자리 확장 방식이므로 밉 레벨이 셀 사이로 번지지 않음 |
| **절차적 / 혼합 머티리얼** | 머티리얼별 선택적 Cycles 베이크 |
| **원본** | 기본적으로 메시에서 제거되며 파일에는 유지됨 |

> 📝 **Material Combiner는 더 이상 지원되지 않습니다.** Shotariya의 Material Combiner를 구동하던 *아틀라스 생성기 (레거시)* 패널은 `5.3.1.0`에서 제거되었습니다. Material Combiner가 여전히 설치되어 있다면 **Import Material Combiner Settings** 버튼([출력](#output) 참조)이 그 설정을 내장 도구로 복사합니다.

> 🧪 **이 도구는 여전히 알파로 표시되어 있습니다.** 처음부터 끝까지 작동하며 테스트되었지만, 내보내기 전에 결과를 확인하고 백업을 보관하며 이상한 점이 있으면 알려 주세요. 실행 취소가 작동하며 원본 머티리얼은 파일에 남습니다.

### 아틀라스 생성기

내장 아틀라스 도구입니다. 추가 애드온도, Pillow도 필요하지 않습니다. 모든 것이 Blender에 포함된 numpy로 실행되므로 설치 프로그램도, 관리자 권한 프롬프트도, 재시작도 필요 없습니다.

빌드 결과는 레이어별로 `Cats_Atlas_Mat_01`이라는 이름의 Principled BSDF 머티리얼 하나(추가 레이어는 02, 03…), 맵별로 `Cats_Atlas_01`, `Cats_Atlas_01_Normal`, `Cats_Atlas_01_Emission` 등으로 명명된 아틀라스 이미지 하나, 그리고 포함된 모든 면의 UV가 아틀라스로 다시 작성된 상태입니다. 동일한 셀을 생성할 머티리얼(같은 텍스처, 같은 색조)은 자동으로 하나의 셀을 공유합니다.

각 빌드는 파일에서 아직 사용되지 않는 이름을 받습니다. 예를 들어 같은 파일에서 두 번째 아바타를 아틀라스 처리하여 `Cats_Atlas_01`이 이미 존재한다면 새 빌드는 `Cats_Atlas_01_2` / `Cats_Atlas_Mat_01_2`(그다음 `_3` 등)로 명명되므로 이전 아틀라스가 절대 덮어쓰이지 않습니다.

하나의 메시를 공유하는 오브젝트(Alt+D로 만든 연결된 복제본)는 메시당 한 번만 처리되므로 공유 UV가 한 번만 다시 작성됩니다.

#### 머티리얼

**Generate Material List**(이후 **Update Material List**)를 클릭하면 장면의 모든 메시와 그 머티리얼을 나열합니다. 각 머티리얼 행에는 다음이 있습니다:

- **Include** 체크박스: 아틀라스에 포함할지 여부
- Cats가 셰이더를 통해 머티리얼의 텍스처를 찾지 못하고 추측해야 했을 때 표시되는 ⚠ 아이콘. 보통 절차적이거나 많이 혼합된 머티리얼을 의미하므로 해당 머티리얼에 **Bake**를 켜는 것을 고려하세요
- **Bake** 토글: 텍스처를 복사하는 대신 Cycles로 이 머티리얼을 렌더링합니다 ([베이킹](#baking) 참조)
- **Layer** 번호: 같은 레이어의 머티리얼은 하나의 아틀라스를 공유합니다. 레이어를 사용하면 한 번의 실행으로 여러 아틀라스를 만들 수 있습니다. 예를 들어 몸용 하나, 의상용 하나

행을 클릭하면 목록 아래에서 해당 머티리얼별 설정을 볼 수 있습니다:

- **Multiply Color**: 머티리얼의 베이스 컬러를 텍스처에 곱합니다. 기본적으로 켜짐
- **Width** / **Height**가 있는 **Custom Size**: 이 머티리얼의 셀을 전역 최댓값보다 작게 제한합니다

목록을 새로 고쳐도 체크와 레이어는 유지됩니다. 이전 실행의 `Cats_Atlas_Mat_*` 머티리얼은 나열되지만 기본적으로 선택 해제되어 있으므로 다시 빌드해도 이전 아틀라스를 아틀라스 처리하지 않습니다.

#### 아틀라스 설정

- **Atlas Size**: 패킹된 크기를 반올림하는 방식. **Power of 2**(기본값, VRChat과 Unity가 원하는 방식), **Quadratic**(정사각형), **Automatic**(정확한 패킹 크기), **Custom** 및 **Strict Custom**
- **Max Width** / **Max Height**: 아틀라스가 이 값을 초과하지 않습니다. 셀은 맞추기 위해 비례적으로 축소됩니다. 기본값 4096
- **Padding**: 각 셀의 테두리를 이 픽셀 수만큼 바깥으로 확장합니다. 게임 내에서 낮은 밉 레벨에 인접 셀이 서로 번지는 것을 막는 역할을 합니다. 기본값 4. 패딩 때문에 아틀라스가 다음 2의 거듭제곱으로 커지지는 않으며, 대신 셀이 1퍼센트 미만을 양보합니다
- **Color Size**: 컬러는 있지만 텍스처가 없는 머티리얼의 셀 크기. 기본값 32
- **Max Tiling**: UV가 0–1 범위를 벗어날 때 머티리얼이 요청할 수 있는 최대 텍스처 반복 수. U = 900에 있는 잘못된 버텍스가 거대한 셀을 만드는 것을 막습니다. 기본값 8
- **Crop to UVs**: 각 텍스처에서 UV가 실제로 사용하는 부분만 아틀라스에 들어갑니다. 기본적으로 켜짐이며, 끄면 전체 텍스처를 유지합니다
- **Pixel Art**: 픽셀 아트 텍스처를 위한 최근접 이웃 리샘플링
- **Remap All UV Maps**: 텍스처가 샘플링하는 UV 맵만이 아니라 모든 UV 맵을 다시 작성합니다. 기본적으로 꺼짐이며, 아바타의 보조 UV 맵은 보통 다른 용도로 사용됩니다
- **Remove Original Materials**: 아틀라스 때문에 사용되지 않게 된 머티리얼 슬롯을 제거합니다. 기본적으로 켜짐. 머티리얼 데이터블록은 퍼지할 때까지 파일에 남으므로 잘못된 빌드는 실행 취소뿐 아니라 수동으로도 복구할 수 있습니다

#### 맵

알베도는 항상 생성됩니다. **Normal**, **Emission**, **Roughness**, **Metallic**, **Ambient Occlusion**, **Height** 중 원하는 것을 선택하면 동일한 레이아웃에서 해당 맵도 생성되며, 각각 올바른 색 공간(알베도와 이미션은 sRGB, 나머지는 Non-Color)을 사용합니다. 노멀과 이미션은 기본적으로 켜져 있습니다.

> Blender 5.3에서는 Cats가 이름이 아닌 표준 상호운용 ID로 색 공간을 설정하므로, "sRGB"나 "Non-Color"라는 공간이 없는 사용자 지정 OpenColorIO 구성(예: ACES)에서도 아틀라스가 올바르게 나옵니다. Blender 5.2에서는 이름이 사용됩니다.

색상은 Blender가 셰이딩하는 방식대로 처리됩니다. 베이스 컬러와 색조는 알베도나 이미션 아틀라스에 반영되기 전에 sRGB로 변환되고, 색조는 선형 공간에서 곱해지며, 16비트 / float 텍스처(EXR, HDR, 16비트 PNG)도 sRGB로 인코딩됩니다. `5.3.1.0` 이후로 이 덕분에 단색 및 색조가 적용된 머티리얼이 뷰포트와 일치합니다. 이전 빌드는 이를 눈에 띄게 너무 어둡게 기록했습니다.

맵은 포함된 머티리얼 중 하나라도 실제로 해당 데이터를 가진 경우에만 기록됩니다. 알베도만 있는 모델에서 똑같은 회색 이미지 일곱 장이 나오지는 않습니다. 앰비언트 오클루전은 추적할 셰이더 입력이 없으므로 텍스처 이름으로 매칭되며 항상 ⚠로 표시됩니다.

- **Pack for Unity**: Metallic과 Roughness를 모두 켜면 별도의 두 이미지 대신 하나의 `_MetallicSmoothness` 맵(RGB에 메탈릭, 알파에 스무스니스)을 기록합니다. 이것이 Unity의 Standard 셰이더가 받는 형식입니다
- **Secondary Scale**: 알베도를 제외한 모든 맵의 해상도에 대해 **Full**, **Half**, **Quarter**. 노멀과 러프니스 아틀라스는 전체 해상도가 거의 필요 없으며, 레이아웃을 공유하기 때문에 UV 변경도 필요하지 않습니다

생성된 머티리얼에서 노멀은 Normal Map 노드를 통해 연결되고, 이미션은 강도 1을 받으며, 러프니스와 메탈릭은 해당 입력에 연결됩니다. AO, 높이, 패킹된 맵은 이미지 노드로 추가되지만 연결되지 않은 상태로 남습니다. 이들은 Unity에서 할당하기 위해 존재합니다.

머티리얼은 Principled BSDF를 사용하는 첫 번째 포함 머티리얼의 표면 설정(러프니스, 메탈릭, 스페큘러, IOR, 코트 및 시인)을 복사하므로 아틀라스 처리된 모델은 원본과 같은 방식으로 셰이딩됩니다. 그런 머티리얼이 없으면(MMD, 툰 또는 MToon 셰이더) 스페큘러 없이 디퓨즈 전용이 되며, 이는 해당 셰이더의 모양과 MMD 모델 수정이 내보내기 셰이더를 설정하는 방식과 일치합니다.

#### 베이킹

**Bake** 토글이 켜진 머티리얼의 경우, Cats는 텍스처를 복사하는 대신 Cycles로 활성화된 각 맵을 렌더링합니다. 절차적, 레이어 또는 버텍스 컬러 머티리얼은 복사할 단일 이미지가 없지만 렌더링할 수는 있습니다.

- **Bake Size**: 베이크되는 각 머티리얼의 정사각형 해상도. 기본값 1024
- **Bake Samples**: Cycles 샘플 수. 앰비언트 오클루전만 몇 개 이상이 필요합니다. 기본값 8

베이크 머티리얼이 있는 모든 오브젝트는 함께 베이크되므로, 여러 오브젝트에서 사용되는 머티리얼은 모든 오브젝트의 면을 담은 하나의 이미지를 갖게 됩니다.

베이크가 건드리는 모든 렌더 설정(엔진, 베이크 출력 대상, 샘플, 장치, 베이크 패스)은 이후에 복원되며, 실패한 경우에도 마찬가지입니다. 베이킹은 항상 CPU를 사용하고 항상 이미지 텍스처로 베이크하므로, 베이크 출력이 Color Attributes로 설정되어 있어도 버텍스 컬러가 덮어쓰이지 않습니다.

> ⚠ 현재 뷰 레이어에 없는 오브젝트(예: 제외된 컬렉션에 있는 오브젝트)는 베이크할 수 없습니다. 빌드는 해당 오브젝트 이름을 언급하며 오류와 함께 중단됩니다.

> ⚠ **Cycles에는 메탈릭이나 높이에 대한 베이크 패스가 없으므로** 이 두 맵은 항상 복사되며 절대 베이크되지 않습니다. 둘 중 하나가 활성화된 상태로 베이크를 실행하면 경고가 해당 맵 이름을 알려 줍니다.

> ⚠ **베이킹은 머티리얼의 기존 UV 레이아웃을 사용합니다.** 대칭 지오메트리는 문제없습니다. 아일랜드가 겹치면 마지막 쓰기가 우선하며, 이는 그 경우에 원하는 동작입니다. 실제로 겹치지만 *서로 다른* 아일랜드는 같은 픽셀을 두고 싸우게 됩니다. 패널은 베이크가 켜진 머티리얼이 하나라도 있으면 이 주의 사항을 표시합니다.

#### 출력

- **Save Atlas**: **Pack into .blend**(기본값) 또는 **Save to Folder**. 후자는 각 맵을 PNG로 **Folder**에 기록합니다. 기존 파일은 절대 덮어쓰지 않고 `_2`, `_3`… 접미사가 추가됩니다. 폴더가 비어 있거나 쓸 수 없으면 빌드는 여전히 성공하고 경고하며, 이미지는 잃지 않도록 대신 .blend에 패킹됩니다
- **Import Material Combiner Settings**: Material Combiner 애드온이 여전히 설치되어 있는 동안에만 표시되며, 전환을 돕기 위한 것입니다. 아틀라스 크기, 치수, 자르기, 픽셀 아트, 컬러 크기, 저장 경로와 머티리얼별 설정, 머티리얼 체크 및 레이어를 아틀라스 생성기로 복사합니다. 패커 선택은 이전되지 않으며(패커는 하나뿐) **Gaps** 값은 의미가 다르지만 **Padding**으로 복사됩니다. 오퍼레이터가 두 가지를 모두 보고합니다

#### 빌드

- **Preview Result**: 아무것도 기록하지 않고 패킹하며, 레이어별로 몇 개의 머티리얼이 몇 개의 셀로 들어갔는지, 아틀라스 크기와 채움 비율을 보고합니다
- **Create Atlas**: 빌드합니다. 보고 줄은 예를 들어 `Layer 1: 10 materials packed into 3 cells, 2048x1024, 96% filled, 2 maps`와 같이 표시됩니다

레이어에서 선택된 모든 머티리얼이 결국 하나의 텍스처를 공유한다면 패킹할 것이 없으므로, Cats는 단순히 그것들을 텍스처 자체 크기의 하나의 머티리얼로 병합하고 그렇게 알려 줍니다. 선택된 머티리얼이 하나뿐인 레이어는 오류입니다. 결합할 것이 없기 때문입니다.

#### 알려진 제한 사항 (알파)

- 출력은 항상 단순한 Principled BSDF입니다. MMD 툰 및 스피어 셰이딩, MToon 및 기타 셰이더 특유의 모양은 유지되지 않습니다. 아틀라스는 FBX를 통해 Unity로 보내는 것을 전제로 합니다
- 범위를 벗어난 UV는 아일랜드가 아닌 머티리얼 단위로 처리됩니다. 하나의 아일랜드가 0–1에 있고 다른 하나가 5–6에 있는 머티리얼은 6타일 너비의 셀을 받습니다. 드문 경우이며 **Max Tiling**이 이를 제한합니다
- **Custom** 크기 모드는 현재 **Automatic**과 동일하게 동작합니다
- 미리 보기는 **Bake Size**를 고려하지 않습니다

#### 순서

눈 추적과 입 모양 **전에** 아틀라스를 생성하세요. 아틀라스 작업은 셰이프 키가 아닌 머티리얼과 UV를 변경하지만, [FAQ](FAQ)의 워크플로는 여전히 적용됩니다.

## 최적화 워크플로

### 권장 순서

1. **메시 정리:**
   - 변형 적용
   - 필요하면 메시 결합
   - 중복 버텍스 제거
   - 셰이딩이 잘못되어 보이면 노멀 재계산

2. **셰이프 키:**
   - 미사용 셰이프 키 제거 및 정적 셰이프 키 최적화

3. **머티리얼:**
   - 머티리얼 결합

4. **아틀라스 생성:**
   - 아틀라스 생성기로 텍스처 아틀라스 생성
   - 머티리얼 수 감소

5. **본 및 웨이트:**
   - 본 병합
   - 미사용 본과 웨이트 정리

6. **최종 확인:**
   - 애니메이션 테스트
   - 머티리얼 확인
   - 버텍스 수 확인

### 성능 팁

- 아틀라스 작업이 가장 큰 성능 향상을 제공합니다
- 본 병합은 플랫폼 제한을 충족하는 데 도움이 됩니다
- 머티리얼 결합은 드로우 콜을 줄입니다
- 중복 버텍스 제거는 버텍스 수를 줄입니다
